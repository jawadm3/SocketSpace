# Step C: Foundations

- **Dates:** 2026-10-02 (session 2 built C1 to C6; session 3 fixed the CodeQL findings and closed
  the stage).
- **Status:** Done. Pushed to `main`; CI and CodeQL green; no open code-scanning alerts.

## Goal

From `docs/development/plan.md`: a secure skeleton where a signed-in user can open a live,
authenticated connection, with CI guarding every push. Think of it as the foundations, wiring and
locks of a house before any rooms are decorated: nothing a visitor would admire yet, but
everything later stages stand on.

## What was built, and how it works

### C1: Tooling (`94e79d9`)

- **Secret scanning.** `scripts/tools/gitleaks.mjs` downloads gitleaks 8.30.1 once, checks it
  against a SHA-256 checksum pinned in the script (copied from the official release's checksum
  file), and keeps it in `.cache/tools/` on D:. A git pre-commit hook (`.githooks/pre-commit`,
  switched on by `pnpm install`) scans every commit before it is made; `pnpm secrets:scan` scans
  the whole history. _Like a metal detector at a door: it checks everything going in._
- **Environment validation** (`packages/shared/src/env.ts`). Each program describes the settings
  it needs; at start-up it stops with a message naming every missing or malformed setting, and
  never prints a value.
- `CHANGELOG.md`, the root lint task for `scripts/`, and Playwright's browsers kept in
  `.cache/ms-playwright` on D:.

### C2: Database (`b5c2f8b`)

- **Schema for all 32 tables** in `docs/architecture/data-model.md`, written with Drizzle (the
  plan only required the tables Stages C and D need). Better Auth's tables are extended with
  profile, theme, onboarding and safety columns.
- **Migrations.** `0000` was generated by drizzle-kit and read line by line; `0001` makes the
  moderation audit log append-only with a database trigger (UPDATE and TRUNCATE always refused,
  DELETE only for rows older than the 365-day retention).
- **`sendMessage`**, the heart of messaging. In one transaction it locks the conversation row,
  returns the original if this client ID was already used (so a retry never creates a duplicate),
  checks every permission, and only then takes the next sequence number. A refused or repeated
  message never uses a number, so a gap always means "you missed something". _Like a deli ticket
  machine that only tears off a ticket once your order is accepted._
- **Two test engines.** Tests run on PGlite (PostgreSQL inside the test process, nothing to
  install) by default, and on a real PostgreSQL when `TEST_DATABASE_URL` is set; each test file
  creates and drops its own database.
- **Local PostgreSQL 17.9 without Docker** (`pnpm db:start`, D-026), on 127.0.0.1 only.

### C3: Shared contracts (`38e940e`)

- **Zod schemas for every real-time event** in `realtime-protocol.md` (community and random
  mode). They are strict: unknown fields are refused. The Socket.IO TypeScript types are derived
  from the same tables, so the browser and the server cannot disagree about a message's shape.
- Acknowledgement and error shapes with nine error codes; text clean-up (Unicode normalisation,
  control and bidi characters removed, lengths counted the way PostgreSQL counts them).
- **Profile rules:** nickname pattern, reserved names and suggestions; real-name visibility per
  viewer (D-024); avatar configs limited to the 42 CC0 DiceBear styles (D-023).
- **Signed internal events** (HMAC-SHA256, 60-second window, constant-time comparison) for the web
  app to tell the realtime server things like "this session was revoked".
- **Authorisation module**, deny by default, with a table-driven test of every actor × action in
  public rooms, private rooms and DMs (SEC-13).
- `scripts/check-source-chars.mjs` refuses invisible or bidi characters in source files (the
  "Trojan Source" trick), because such characters had landed in files by accident while writing.

### C4: Web app (`cfbe9ba`)

- **Next.js 16.3 + Better Auth 1.7** on the shared database, with UUID v7 IDs.
- **Sign-in methods:** email and password (10 to 128 characters, checked against Have I Been Pwned
  using only the first 5 characters of the password's hash), email verification, single-use
  30-minute password reset that signs out every session, passkeys, guest sessions, and six social
  providers switched on from environment variables only (Google, Facebook, GitHub, Discord,
  Microsoft, LinkedIn). Facebook and Microsoft never link to an existing account by email (D-022,
  D-029).
- **Protections added on top of Better Auth** (D-029): rate limits stored in the database (3
  sign-ins per 10 s per IP), a per-account lockout with growing waits, refusal of cross-site
  state-changing requests (closes "login CSRF"), and risky built-in endpoints switched off.
- **Pages:** sign in (D-022 layout with a "Last used" badge), sign up, forgot and reset password,
  onboarding (nickname with suggestions and a CC0 avatar preset are required; it cannot be
  skipped), app home with a "verify your email" banner, and "Devices and sessions" with
  revocation that also disconnects live sockets.
- **Security headers and a per-request nonce Content Security Policy**; the theme is read from a
  cookie on the server so the first frame is already right (Airmail by default; the other two
  themes come in Stage F).
- **`POST /api/realtime/token`:** same-origin only, active accounts only, 30 per minute, returns a
  5-minute signed token (EdDSA) that carries only the user ID, session ID, role and guest flag.
- **Email drivers:** Resend (for production, Stage H), a file "mail catcher" for development
  (`/dev/mail`) and an in-memory one for tests. `pnpm setup:local` writes local `.env.local` files
  with generated development secrets that are never printed.

### C5: Realtime server (`304920f`)

Every connection passes these checks before it is accepted, in this order: allowed `Origin`
(checked in `allowRequest`, so CORS is not the only guard; v1's foreign-origin probe is now
refused), token signature against the web app's public keys (JWKS), issuer, audience, expiry and
claim shapes, a live session, an active account without a ban or suspension, and connection caps
(10 per user, 20 per IP, 30 new per IP per minute). Packets over 16 KB are refused. _Like a
building's front desk that checks the badge, the visitor list and the guest count before the lift
door opens._

- **`message:send`** stores through `sendMessage` (permissions checked inside the numbering
  transaction), replies with an acknowledgement carrying the stored message and broadcasts
  `message:new` once; a repeat with the same client ID is acknowledged but not re-broadcast.
- **`sync:request`** returns what changed after each conversation's last-seen number, for
  conversations the person belongs to only.
- **One wrapper for every event:** an acknowledgement is required, input is validated with the
  shared schemas, per-user token buckets limit the rate (20 violations a minute disconnects), and
  failures are reported as `UNAVAILABLE` or `INTERNAL` without details. Logs carry error names and
  codes only (D-033), with pino redaction as a second safety net.
- **Internal events** (`POST /internal/events`, HMAC-signed, replay guard): revoked sessions and
  sanctions disconnect sockets; membership changes join or leave rooms. An **outbox** table holds
  events the web app could not deliver; it is drained at start-up and at most every 10 seconds
  after database work, never on an idle timer (so a sleeping free-tier database is not woken).
- `/healthz`, `/readyz` and a token-protected Prometheus `/metrics`; **graceful shutdown** tells
  clients to reconnect and waits for in-flight writes; a Redis adapter behind `REDIS_URL` for more
  than one instance.
- **One-file bundle** (esbuild, 3.3 MB) and a Dockerfile that ships only Node.js and that file,
  running as the `node` user (D-031).
- The web app's `/app` page shows the live connection status and fetches a fresh token on every
  reconnect.

### C6: CI (`2792e87`, `4d31e43`)

`.github/workflows/ci.yml` runs six jobs in parallel on every push and pull request:

| Job                        | What it does                                                                                                                                        |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| Lint, types, unit, build   | Formatting, lint, type checks, every test suite on PGlite, builds of both apps                                                                      |
| PostgreSQL 17 and Redis    | Every suite against a real PostgreSQL service container, plus two realtime servers sharing Redis                                                    |
| End-to-end (Playwright)    | Journeys against production builds of both apps                                                                                                     |
| Docker images              | Builds both images, starts them, probes them (non-root user, health, origin refusal, metrics token, CSP nonce, JWKS, readiness), stops with SIGTERM |
| Secret scan (full history) | gitleaks over every commit                                                                                                                          |
| Dependency audit           | `pnpm audit`; fails on high or critical advisories                                                                                                  |

`codeql.yml` runs GitHub's security-and-quality queries on every push and weekly. Every action is
pinned to a full commit SHA, and the workflow token is read-only by default.

### Close-out: gaps found while updating the requirements matrix (session 3)

Before marking a requirement Done, each "done when" criterion was checked against a real test.
Five gaps turned up and were closed rather than reported as done:

- **OBS-01 asked for "request IDs" in the logs; there were none.** Every realtime HTTP response
  now carries an `X-Request-Id`, written on any log line about that request, and every log line
  about a connection carries its Socket.IO `socketId` (new "connection accepted" and "connection
  closed" lines at debug level). _Like a ticket number at a help desk: staff can find your case
  without repeating what you said._ Two new tests.
- **HIST-01 asked that messages "survive server restart"; no test restarted the server.** The test
  harness can now stop a server and start a fresh one on the same database. A new test sends two
  messages, restarts, resyncs them from the new server, and checks that the next message is
  number 3 (no gap, no reuse). It passes on PGlite and on real PostgreSQL 17.9.
- **The web app's logger still wrote error messages** (D-033 says names and codes only, because a
  database error's message repeats the query's parameters). It now reduces errors to name and
  code, like the realtime server. Three new tests (`apps/web/src/server/log.test.ts`).
- **AUTH-13 covers Facebook and Microsoft; only Facebook was tested.** A stubbed Microsoft sign-in
  (claiming a "verified" email that matches an existing account) is now refused like Facebook's.
  To prove the test can fail, the protection was removed for a moment: the test then failed with
  the sign-in landing on `/app` (account taken over). Protection restored, file unchanged.
- **AUTH-02 says a verification link "verifies once"; nothing checked that.** Verification also
  signs the person in, so a link that worked twice would be a reusable sign-in link. A new test
  shows the first use starts a session and a second use only answers "already verified" and
  starts none.

## Upstream report for Better Auth (D-030)

The owner may want to report this to Better Auth (it needs the owner's GitHub account). Suggested
text:

> **Title:** Signing in with a stale session cookie silently signs the user out again when the
> anonymous plugin is enabled (1.7.6)
>
> **Steps:** enable the `anonymous` plugin. Sign in with email and password in a browser. End that
> session elsewhere (for example a password reset, which revokes all sessions), so the browser
> still holds a cookie for a session that no longer exists. Sign in again with email and password
> in that browser.
>
> **Expected:** the new session cookie is set and the user is signed in.
>
> **Actual:** the sign-in response sets the new session cookie, but the anonymous plugin's after
> hook looks up the session named by the _old_ cookie, does not find it, and appends headers that
> delete the session cookie. The browser applies them last, so the user is signed out straight
> away with no error.
>
> **Workaround:** a `before` hook on session-starting paths removes a session cookie that no longer
> matches a live session from the incoming request.
